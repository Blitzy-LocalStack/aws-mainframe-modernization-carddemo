# =============================================================================
# requirements-test.txt  --  AWS CardDemo automated test-suite Python toolchain
# =============================================================================
#
# Purpose:
#   Fully pinned, SHA-256-hash-locked dependency closure for the CardDemo
#   test harness (pytest orchestration, coverage, and the LocalStack/AWS
#   dataset-staging layer). Every distribution in the transitive closure is
#   listed with the exact SHA-256 of the artifact resolved on the reference
#   platform, so `pip install --require-hashes` reproduces a byte-identical
#   environment and fails closed on any tampered or substituted artifact --
#   the supply-chain integrity bar expected of financial-enterprise software.
#
# Reference platform (the artifacts hashed below were resolved here):
#   CPython 3.13 (cp313), Linux x86_64 (manylinux2014 / manylinux_2_17).
#   WHY platform-specific: several wheels in this closure are compiled and
#   therefore platform-tagged (coverage, cryptography, cffi, PyYAML, psutil,
#   ruamel.yaml). Their hashes are valid for the reference platform's wheel.
#   Trade-off: a single-platform hash lock is exact and verifiable here (the
#   CI runner IS this platform per the AAP) but must be regenerated to add a
#   second platform -- see "Regenerating" below. We deliberately do NOT list
#   hashes we cannot verify on this runner, because a fabricated/partial hash
#   is worse than an honest single-platform lock.
#
# Virtual environment (activate BEFORE installing or running the suite):
#   The runner ships a repo-root .venv (Python 3.13). Activate it with either:
#       source .venv/bin/activate          # interactive / CI shell
#   or invoke tools directly without activation:
#       .venv/bin/python -m pytest ...     # e.g. from a runner script
#   WHY: plain `python3 -m venv` fails on this image (the apt pip seed is
#   removed); if the .venv is missing, recreate it with:
#       python3 -m venv .venv --without-pip
#       curl -fsSL https://bootstrap.pypa.io/get-pip.py | .venv/bin/python
#
# Installing (hash-verified, deterministic):
#       source .venv/bin/activate
#       pip install --require-hashes -r tests/requirements-test.txt
#   --require-hashes forces every requirement to be pinned AND hashed (this
#   file satisfies both) and rejects any artifact whose hash does not match.
#
# Regenerating (after a deliberate version bump, or to add a platform):
#       python3 -m pip download -r <direct-deps> --dest <dir>   # full closure
#       # then, per artifact:  python3 -m pip hash <artifact>
#   Commit the refreshed pinned+hashed block. Do this on each target platform
#   and merge the resulting --hash lines under the corresponding package.
#
# LocalStack (included here, unlike the prior revision):
#   `localstack` (and its closure: localstack-client, plux, dnslib, etc.) is
#   pinned below so the AWS-emulation test layer is reproducible from this one
#   manifest. WHY changed: the earlier header claimed LocalStack was managed
#   "separately"; that left the staging layer unlocked and non-reproducible,
#   which is exactly the gap MA-07 flagged. It is now part of the locked set.
#
# awscli version note (drift resolved):
#   Pinned to awscli==1.45.50. WHY: the AAP 0.6.1 table referenced 1.45.49, but
#   the artifact actually installed on the runner -- and the one currently
#   resolvable from PyPI -- is 1.45.50. Pinning the real, installed, hashable
#   version removes the manifest-vs-environment drift MA-07 called out; pinning
#   a version we cannot hash on this runner would reintroduce the drift.
#
# Direct vs transitive:
#   The seven AAP 0.6.1 direct dependencies are each preceded by a one-line
#   `# Direct (AAP 0.6.1): ...` rationale. All other entries are transitive
#   dependencies included to complete the hash-locked closure.
#
# Scope / provenance:
#   Test-only, additive dependencies -- installing this file does not modify
#   the production COBOL/JCL application in any way. The GnuCOBOL toolchain and
#   the GCBLUnit COBOL unit framework are NOT Python packages and are therefore
#   provisioned outside this file (see tests/cobolget.json and tests/import.json
#   for the vendored-COBOL provenance).
# =============================================================================
