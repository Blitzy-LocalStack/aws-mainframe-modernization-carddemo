# WHAT: One SHA-256 digest per record file in this fixture tree, keyed by the file's
#       path relative to this directory, in ascending path order.
#
# WHY : Assumptions: the structural checks in
#       services/batch-service/src/test/java/com/carddemo/batch/fixtures/BatchFixtureContractTest.java
#       pin geometry, line endings, a successful decode and each scenario's discriminating
#       value -- but they cannot pin a field no scenario turns on. A same-width edit to a
#       customer name, a merchant description or an unasserted FILLER byte satisfies every
#       one of them, and for the nine supporting images of master section 1.5 no job run
#       would notice either. This manifest closes that gap: any change to any byte of any of
#       the 62 files fails everyRecordFileMatchesItsCommittedDigest by name.
#
# WHY : Alternatives Considered: (1) leaving the gap and documenting it, which was rejected
#       because master section 1.1 promises "an edit is still detected" and a promise a
#       reader can act on has to be true rather than qualified; (2) asserting digests inside
#       the Java class as string constants, rejected because 62 literals in a test are 62
#       lines a reviewer cannot diff against the files they describe, whereas this format is
#       verifiable independently of the test; (3) a per-scenario manifest, rejected because
#       the closed-set check that catches an ADDED or DELETED file needs one authority over
#       the whole tree.

#             find . -name '*.txt' -not -name 'FIXTURE_DIGESTS.txt' | sed 's#^\./##' | \
#             LC_ALL=C sort | xargs sha256sum > /tmp/b && \
#             cat /tmp/h /tmp/b > FIXTURE_DIGESTS.txt

#       and verify independently of the test suite with:

#           grep -v '^#' FIXTURE_DIGESTS.txt | sha256sum -c -
